# Auntie Som Lab — API Testing

**ชื่อ:** Apiphoom Chuenchompoo

**รหัสนิสิต:** 6633280621

ทดสอบ API ด้วย Bruno โดยไม่แก้ไข `app.py` ชุดทดสอบมี 30 requests ครอบคลุมการล็อกอิน สั่งอาหาร ตรวจราคาและสต็อก รวมถึงข้อมูลที่ไม่ถูกต้อง ทุก request มี test script ตรวจผลอัตโนมัติ

## บั๊กที่พบ

| ปัญหา | วิธีตรวจและผลที่พบ |
|---|---|
| คำนวณราคาขาดไป 5 บาท | ข้อ 08, 09 และ 26 เทียบ `totalPrice` กับราคาเมนู × จำนวน เช่น ก๋วยเตี๋ยว 1 ชามควรเป็น 50 แต่ได้ 45 บาท ทั้งตอนสร้างและอ่านออเดอร์ |
| สั่งเกินสต็อกได้ | ข้อ 24–25 ส่งจำนวนเต็มที่มากกว่าสต็อก ระบบยังตอบ `200` และสต็อกลดจาก 1.5 เป็น -0.5 แทนที่จะปฏิเสธและเก็บสต็อกเดิม |
| รับจำนวนติดลบ ศูนย์ และทศนิยม | ข้อ 12–17 คาดหวัง `400` แต่ได้ `200` ทั้งหมด จำนวน -1 ทำให้สต็อกเพิ่ม ส่วน 0.5 ทำให้สต็อกเป็นทศนิยม |
| จำนวนผิดชนิดทำให้เกิด server error | ข้อ 18–23 ส่งข้อความ, `null` และไม่ส่ง `quantity` ได้ `500` แทน `400` แต่สต็อกไม่เปลี่ยน |
| ไม่พบออเดอร์แต่ตอบว่าสำเร็จ | ข้อ 11 ขอออเดอร์ที่ไม่มีอยู่ คาดหวัง `404` แต่ได้ `200` แม้ response จะมีข้อความ `Order not found` |
| ไม่ตรวจรูปแบบ Bearer | ข้อ 30 ส่ง token โดยไม่มีคำว่า `Bearer` ควรได้ `401` แต่ระบบผ่านไปตรวจสต็อกและตอบ `400 Out of stock` |

ชุดทดสอบกำหนดให้ `quantity` เป็นจำนวนเต็มมากกว่า 0 และจำนวนที่ไม่ถูกต้องต้องได้ `400` แต่ละกรณีจะเทียบสต็อกก่อนและหลัง แล้วอ่านค่าล่าสุดสำหรับกรณีถัดไป เพื่อลดผลกระทบจากบั๊กก่อนหน้า

## วิธีรัน

ใช้ Python 3.10 ขึ้นไป ติดตั้งและเปิด API จากโฟลเดอร์ repository:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install flask
cd auntie-som-noodle-api
python app.py
```

เปิดโฟลเดอร์ `Auntie Som Lab` ใน Bruno เลือก environment `local` ซึ่งมี `baseUrl = http://localhost:5000` แล้วรันทั้ง collection ตามลำดับ 01–30 โดยไม่หยุดเมื่อ test fail สคริปต์หลังล็อกอินจะบันทึก `accessToken` เป็น environment variable และนำไปใช้ใน request ถัดไป ส่วน `orderId` อ่านจากออเดอร์ที่สร้างจริง

**หยุดและเปิด API ใหม่ก่อนรันทั้งชุดทุกครั้ง** เพราะสต็อกและออเดอร์เก็บในหน่วยความจำ อย่ารัน requests พร้อมกัน

รันผ่าน CLI ได้จาก terminal อีกหน้าต่าง โดยเริ่มจากโฟลเดอร์ repository:

```bash
cd "Auntie Som Lab"
npx --yes @usebruno/cli@4.2.1 run --env local
```

ถ้าพอร์ต 5000 ถูกใช้งาน ให้เปิด API ด้วย `python -m flask --app app run --port 5050` จากโฟลเดอร์ backend และเปลี่ยน `baseUrl` เป็น `http://localhost:5050` ใน Bruno หรือเพิ่ม `--env-var baseUrl=http://localhost:5050` ท้ายคำสั่ง CLI

## ผลทดสอบ

รันกับ backend ต้นฉบับด้วย Bruno CLI 4.2.1 และ Python 3.12.13 ผ่านพอร์ต 5050: **51 checks ผ่าน 35 และไม่ผ่าน 16** ข้อที่ไม่ผ่านแสดงบั๊กตามตาราง ไม่ได้แก้ assertion ให้ยอมรับพฤติกรรมที่ผิด ส่วนการล็อกอิน การปฏิเสธ token ผิด สินค้าที่ไม่มี และสินค้าหมด ทำงานตามที่คาดไว้ ดูรายละเอียดใน [test-results.json](test-results.json)

Bruno บันทึกตัวแปรขณะรันลง environment ก่อน push งานให้ล้าง `accessToken` และตัวแปรจากการรัน โดยคง `baseUrl` กับ `accessToken` ว่างไว้เหมือนไฟล์ที่ส่งนี้
